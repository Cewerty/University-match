# ADR 0001: Бот только знакомит: без фото и переписки внутри бота

## Дата: 18-11-2026

## Статус: Accepted

## Контекст

Бот подбирает студентам одного учебного заведения людей с похожими интересами. Среди пользователей могут быть несовершеннолетние: в колледже после 9 класса учатся с 15 лет, рядом с ними учатся совершеннолетние студенты старших курсов.

Любой канал, по которому пользователь может передать другому пользователю произвольный контент (фото, файлы, сообщения), создаёт три проблемы:

1. **Вредный контент.** Нежелательные фото или сообщения, в том числе от взрослого несовершеннолетнему. Для учебного заведения это прямой скандал, и ответственность ляжет на него и на разработчика.
2. **Модерация.** Такой контент нужно проверять, хранить жалобы, принимать решения. У проекта нет ни модераторов, ни регламента.
3. **Персональные данные.** Медиа и переписка — это дополнительные данные, которые надо хранить, защищать и удалять по запросу.

Ограничения проекта: один разработчик, прототип, модерацию и обработку данных может взять на себя только учебное заведение, а договорённостей с ним пока нет.

## Решение

Принято решение, что **бот только знакомит, а общение происходит вне его**: в боте нет ни фото, ни переписки между пользователями. Так работает принцип минимизации данных: не собираем и не передаём ничего, что не нужно для подбора.

### Детали реализации

Уже сделано в коде:

1. Бот сохраняет только данные анкеты: фамилию, имя, отчество (текст), номер телефона (контакт), факультет, группу и интересы.
2. Интересы выбираются из фиксированного списка, который ведёт администратор. Свободного текста об интересах нет.
3. Любое сообщение другого типа (фото, видео, файл, стикер, текст не на своём шаге) уходит в обработчик-заглушку `on_other_messages`: бот отвечает «не получилось разобрать» и ничего не сохраняет.
4. Контакт принимается, только если он принадлежит самому отправителю (`contact.user_id == message.from_user.id`). Пересланную чужую карточку бот отклоняет.

```python
# src/bot/dialogs/register/windows.py: на каждом шаге принимается только один тип данных
MessageInput(func=on_contact_received, content_types=ContentType.CONTACT, id="send_contact_info"),
MessageInput(on_other_messages),  # всё остальное: ответ без сохранения
```

Правило на будущее: **любая функция, которая позволяет пользователю передать произвольный контент другому пользователю, требует нового ADR**, где разобраны модерация, хранение и удаление.

### Что это решение НЕ закрывает

Когда в боте нет переписки, единственным моментом, где один пользователь получает доступ к другому, остаётся **передача контакта**. Сейчас карточка совпадения сразу показывает номер телефона и полное имя, без согласия второй стороны, поэтому бот фактически раздаёт номера.

Эти меры будут реализованы отдельно, каждая со своим ADR:

| Мера | Какую проблему закрывает | Статус |
|---|---|---|
| Взаимное согласие: контакт раскрывается, только когда оба нажали «хочу познакомиться» | Передача контакта без согласия | **Обязательно, следующий шаг** |
| Минимальная карточка до согласия: имя, факультет, общие интересы | Утечка ФИО и номера посторонним | Планируется |
| Вход по коду группы от куратора, позже проверка номера по данным учебного заведения | Посторонние в боте | Планируется |
| Подбор только внутри одного курса | Большой разрыв в возрасте | Планируется |
| Кнопка «пожаловаться / заблокировать» и бан в админке | Злоупотребления после знакомства | Планируется |
| Экран согласия на обработку данных и команда «удалить мои данные» | Персональные данные | Планируется |

Часть вопросов кодом не решается и требует решения учебного заведения: кто оператор персональных данных, кто модерирует жалобы и допускаются ли несовершеннолетние вообще. До письменной договорённости бот работает только на демо-данных.

## Альтернативы

* **Переписка внутри бота (бот пересылает сообщения между пользователями):**
  * *Плюсы:* не нужно раскрывать контакт; можно заблокировать собеседника, не меняя номер; есть журнал на случай жалобы.
  * *Минусы:* переписку надо хранить и модерировать, это больше персональных данных; бот становится каналом для вредного контента, за который отвечает проект.

* **Фото в профиле:**
  * *Плюсы:* профиль выглядит живее, людям проще решиться на знакомство.
  * *Минусы:* второй канал для вредного контента; нужна проверка изображений и хранилище; фото — персональные данные.

* **Анонимный чат через бота с раскрытием контактов по желанию:**
  * *Плюсы:* лучший баланс удобства и приватности.
  * *Минусы:* все минусы переписки внутри бота плюс сложность реализации; без модератора неприменимо.

## Последствия

### Положительные

* [+] Внутри бота нечего модерировать: вредный контент нельзя передать через бота.
* [+] Меньше персональных данных: хранится только анкета.
* [+] Проще объяснить учебному заведению, что делает бот и за что оно отвечает.
* [+] Меньше кода и инфраструктуры: нет хранилища медиа и сообщений.

### Отрицательные

* [-] Меньше вовлечённости: чтобы поговорить, нужно уйти из бота.
* [-] Передача контакта становится единственной точкой риска, и без взаимного согласия она опасна.
* [-] Бот не видит, что происходит после знакомства, и не может это модерировать: остаётся только кнопка жалобы.
* [-] Имя, фамилия и отчество остаются свободным текстом и могут содержать оскорбления; это исправляется в админке.
